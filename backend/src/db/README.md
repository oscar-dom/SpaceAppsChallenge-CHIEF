# `src/db`: database

Drizzle ORM schema, migrations and access functions for the SQLite database. Only the backend writes to it. The full design is in [`docs/database-schema.md`](../../../docs/database-schema.md).

| File | Purpose |
| --- | --- |
| `schema.ts` | Tables and constraints. Mirrors the types of `@chief/shared` |
| `../../drizzle/` | SQL migrations generated by drizzle-kit (never edit by hand) |
| `client.ts` | `createDatabase()`: opens SQLite with `foreign_keys`, WAL and a busy timeout. `':memory:'` for tests |
| `migrations.ts` | `runMigrations(db)` |
| `populate.ts` | `populateDatabase(db, { seed })`: reference data + simulated mission history |
| `queries.ts` | Access functions that return `@chief/shared` types |
| `types.ts` | Types not yet in `@chief/shared` (`Medication`, `Alert.recommendation`); delete once the agent branch is merged |
| `migrate.ts`, `seed.ts`, `reset.ts` | CLIs behind `npm run db:*` |
| `db.test.ts` | Vitest tests (seed, scenarios, queries, constraints) |

## Commands (from the repository root)

```bash
npm run db:generate -w backend   # after editing schema.ts
npm run db:migrate -w backend
npm run db:seed -w backend
npm run db:reset -w backend
npm run db:reset -w backend -- --restore   # back to the clean copy
npm test -w backend
```

## Changing the schema

1. Edit `schema.ts`.
2. Run `npm run db:generate -w backend` and commit the new file in `backend/drizzle/`.
3. Run `npm run db:reset -w backend` to rebuild your local database (`db:migrate` is enough if you want to keep its data).
4. Update `docs/database-schema.md`. If the change touches a shared type, agree on it with the team first: `shared/` is owned by everyone.

## Rules for writing queries

1. **Go through `queries.ts`**: return `@chief/shared` types (camelCase, string ids), never table rows.
2. **Dates** are simulated time, `YYYY-MM-DDTHH:mm:ssZ` without milliseconds. The database rejects other formats; `toISOString()` adds milliseconds, so strip them (see `toIso()` in `services/simulator/history.ts`).
3. **Repeated inserts**: use `onConflictDoNothing()` and look at `changes`, never at `lastInsertRowid` (it keeps the previous id after an ignored insert).
4. **Long series**: aggregate in SQL instead of returning thousands of rows; `better-sqlite3` is synchronous and blocks the server while it queries.
5. **Mark simulated data** with `simulated: true`. Real data (OSDR) is stored with `false`.
